📝 System Prompts (click to expand)
All prompts below are view-only. Numbering follows the settings-page scheme; backend pipeline step is noted in parentheses. Each card is tagged with the model family it runs on — OCR (dedicated OCR model), VLM (image + text, Qwen VLM), LLM (text-only, Qwen text LLM).
Step 1 — GLM OCR Prompt (backend step01)
Extracts raw text from each PDF page using GLM-OCR model
Step 2 — OCR Cleaning & VLM Text Completion (backend step02)
VLM re-extraction for each page to catch text GLM missed. Includes a main prompt + a fallback used when GLM returns garbage.
Step 3 — Page Classification (Legacy Combined) (backend step03 legacy)
Original single-prompt classifier — kept for back-compat. The new pipeline uses Steps 4-8 below.
Step 4 — Document Type Classification (Step 3a) (backend step03 sub)
Per-page doc_type + is_continuation. Text-dominant, runs first in the 3-way split.
Step 5 — Markings & Seals (Step 3b) (backend step03 sub)
Visual-only. Extracts stamps, signatures, seals, logos per page at higher resolution.
Step 6 — Copy / Original Status (Step 3c) (backend step03 sub)
Narrow question: find ORIGINAL / COPY / NON-NEGOTIABLE / FIRST-ORIGINAL marker and report copy status.
Step 7 — BL Sub-type (Step 3d) (backend step03 sub — BL packets only)
Packet-level. Classifies BL as short-form / charter-party / master / house / forwarder with overleaf & blank-back detection.
Step 8 — Packet Summary (Step 3e) (backend step03 sub — all packets)
Packet-level structured summary across all pages using the text LLM.
Step 9 — Packet Validator (Step 3f) (backend step03 sub)
LLM-based validator: does the packet's combined text support its classification? Used to flag mis-classifications.
Step 10 — Page Re-check (Step 3g) (backend step03 sub)
Neighbour-context re-classification. Triggered when a packet fails validation — pages are re-sent with prev/next page types as context.
Step 11 — MT Identification (backend step04)
Classifies document packets into MT-side (SWIFT LC) vs shipping-side
Step 12 — MT Reconciliation (backend step05)
LLM cross-check of GLM OCR on SWIFT MT-side pages to catch missed fields
Step 13 — LC Field Extraction (backend step06)
LLM extraction of SWIFT fields from scanned LCs when OCR regex fails
Step 14 — LC Amendment Processing (backend step06)
Parses MT707 amendments and applies them to the base LC to produce the Final LC
Step 15 — Shipping Classification (backend step08)
Matches shipping documents against LC requirements with field extraction
Step 16 — Shipping Reconciliation (backend step09)
LLM reconciliation on shipping documents to resolve OCR ambiguities and extract structured fields
Step 17 — Decomposition (System) (backend step12)
System instructions for breaking LC clauses into individual checkable conditions
Step 18 — Decomposition (User Template) (backend step12)
Per-clause user prompt template sent alongside the Decomposition system prompt
Step 19 — Verification (backend step14)
Checks each condition against shipping documents with critical rules + post-check overrides
